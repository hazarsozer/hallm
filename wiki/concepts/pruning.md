## Definition
Pruning removes parameters (weights, neurons, attention heads, or entire layers) that contribute little to model output. The goal is to create a sparse or smaller network that maintains most of the original model's accuracy while requiring less compute and memory at inference time.

## Major Variants

- **Unstructured pruning**: Individual weights are zeroed out. Achieves highest compression ratios but requires sparse matrix hardware support for actual speedup.
- **Structured pruning**: Removes entire neurons, heads, or layers. Hardware-friendly — produces smaller dense matrices — but typically sacrifices more accuracy than unstructured.
- **Magnitude-based (iterative)**: Prune weights with smallest absolute values, then retrain; repeat. **Han et al. (2015)** [arxiv:1506.02626] established the foundational three-step pipeline: train connectivity → prune connections below per-layer threshold → retrain with L2 reg and adjusted dropout D_r = D_o·√(C_ir/C_io). Key findings: iterative pruning doubles ratio vs single-pass (5× → 9× on AlexNet); first CONV layer most sensitive (only 3 input channels); FC layers tolerate 92% pruning; weight distribution becomes bimodal post-prune; sparsity pattern reveals visual attention (banded center structure in LeNet-300-100 FC1). AlexNet 9× (61M→6.7M), VGG-16 13× (138M→10.3M), no accuracy loss. Direct precursor to Deep Compression Stage 1. See 1506.02626. **The Lottery Ticket Hypothesis** [arxiv:1803.03635] (Frankle & Carbin, MIT, ICLR 2019) explains *why* iterative magnitude pruning works: dense networks contain "winning ticket" subnetworks f(x; m⊙θ₀) that, trained from their original initialization, match or exceed the full network at ≤10-20% of parameters. The critical insight is the **weight rewind** step — surviving weights are reset to their original initialization θ₀ (not randomly reinitialized). Random reinitialization destroys performance; structure alone is insufficient. Winning tickets at ≤10-20% of size learn faster and reach higher accuracy than the original. Works across SGD/momentum/Adam, dropout, batchnorm, residual connections. Iterative pruning finds smaller winning tickets than one-shot. See [[sources/1803.03635]].
- **Gradient/sensitivity-based**: Use gradient information to identify less important connections. **Optimal Brain Damage (OBD)** [LeCun, Denker, Solla, NeurIPS 1990] is the foundational paper: saliency(i) = ½ h_ii u_i² where h_ii = ∂²E/∂u_i² is the diagonal Hessian. Three approximations make it tractable: diagonal (ignore cross-terms), extremal (at minimum g_i≈0), quadratic. Magnitude ≠ saliency: a small weight with large second derivative is more important than a large weight with small second derivative. Direct ancestor of GPTQ (OBD/OBS lineage for quantization) and SparseGPT (full Hessian, one-shot). See lecun1990-obd.
- **Gradient-sensitivity at initialization**: **SNIP** [arxiv:1810.02340] (Lee, Ajanthan, Torr, Oxford, ICLR 2019) prunes the network *once before training* using connection sensitivity: s_j = |∂L/∂c_j| / Σ|∂L/∂c_k| where c_j is a binary indicator variable gating each connection (evaluated at Glorot initialization with a single mini-batch). Scale-invariant, no pretraining required, no iterative cycles, no extra hyperparameters. Achieves virtually reference accuracy on MNIST, CIFAR-10, Tiny-ImageNet at extreme sparsity; matches LWC/DNS/OBD at far lower compute cost. Works on CNNs, ResNets, RNNs without modification. For HaLViT: SNIP's gradient w.r.t. shared W automatically accumulates signal from both W→x and Wᵀ→x' paths in one backward pass, making it naturally suited to shared-weight pruning. See [[sources/1810.02340]].
- **Activation-based**: **Wanda** [arxiv:2306.11695] (Sun, Liu, Kolter — CMU/Meta, ICLR 2024) scores weights by |w_ij| × ||x_j||₂ and prunes the lowest-scoring weights per output neuron. No retraining, no weight update, no Hessian — only a calibration forward pass (128 C4 sequences). Motivated by LLM.int8()'s emergent large-magnitude feature finding: a weight on a high-activation channel matters more than a large weight on a low-activation channel. LLaMA-7B 50% unstructured: 7.26 PPL vs 17.29 for magnitude pruning; competitive with SparseGPT (6.97) without any weight update. At 65B+, both Wanda and SparseGPT achieve lossless 50% sparsity — overparameterization effect. For HaLViT: activation norms for shared W accumulate from all forward passes through W (both W→x and Wᵀ→x' paths) — joint saliency signal with no modification, and simpler than SNIP (no backward pass needed). See [[sources/2306.11695]].
- **One-shot LLM pruning**: **SparseGPT** [arxiv:2301.00774] prunes massive LLMs without any retraining using second-order Hessian approximations. Key contribution: Hessian Synchronization — a shared recursive sequence of inverse Hessians (H_{U_j})^{-1} across all weight rows, computed via Gaussian elimination in O(d_col³) total rather than O(d_row × d_col³). OPT-175B reaches 50% sparsity in 4.5h on a single A100, with PPL 8.21 vs dense 8.34 — overparameterization means 100B+ weights can be dropped without loss. Supports 2:4 semi-structured sparsity (1.54–1.79× GPU speedup on Ampere). Merges with GPTQ into a single pass for joint sparsification+quantization. See [[sources/2301.00774]].
- **Movement-based (fine-tuning regime)**: **Movement Pruning** [arxiv:2005.07683] (Sanh, Wolf, Rush, Hugging Face/Cornell, NeurIPS 2020) addresses the transfer learning gap: magnitude pruning fails when weight values are mostly fixed by pretraining rather than the fine-tuning objective. Movement pruning introduces a parallel score matrix S and uses STE to learn scores jointly with weights during fine-tuning: ∂L/∂S_{i,j} = (∂L/∂a_i)·W_{i,j}·x_j. Scores increase when weights move away from zero (fine-tuning reinforcing the connection) and decrease when weights move toward zero (fine-tuning suppressing it). Mask M = Topv(S). Hard variant uses discrete Topv; soft variant uses continuous threshold + sigmoid regularizer. BERT: 95% performance at 5% encoder weights on MNLI/SQuAD v1.1; with distillation: 3% parameters retained at minimal loss. At extreme sparsity (<15% remaining), dramatically outperforms magnitude pruning. Naturally handles shared weights — gradient accumulates from both W→x and Wᵀ→x' per step. See 2005.07683.
- **Blockwise differentiable pruning**: **BESA** [arxiv:2402.16880] (Xu, Shao, Luo et al. — OpenGVLab/Shanghai AI Lab, 2024) is the first differentiable LLM pruning algorithm. Two innovations: (1) minimize blockwise reconstruction error (attention + FFN block together) instead of layer-wise — prevents error accumulation across layers; (2) per-layer sparsity rates learned via differentiable binary masks + STE (2.10% extra parameters per block in LLaMA1-7B) — no manual hyperparameter tuning. LLaMA2-70B 50% pruning: +0.16 PPL better than SparseGPT in 5h on one A100-80GB. For HaLViT shared W: block-level error objective integrates both W→x and Wᵀ→x' uses simultaneously — no special handling needed for shared-weight pruning. BESA:pruning::OmniQuant:quantization (same philosophy, same lab). See [[sources/2402.16880]].
- **PEFT-compatible pruning**: LoRAPrune and **Diff Pruning** [arxiv:2012.07463] combine pruning with parameter-efficient transfer learning. Diff Pruning specifically reparameterizes θ_task = θ_pretrained + δ_task and sparsifies δ via Hard-Concrete L0; achieves GLUE at 0.5% parameters/task — the sparsest PEFT approach. See peft and 2012.07463.

## Trade-offs

| Dimension | Unstructured | Structured |
|-----------|-------------|------------|
| Accuracy loss | Low | Higher |
| Hardware speedup | Requires sparse hw | Works on standard hw |
| Compression ratio | Very high | Moderate |
| Composability with quantization | Hard | Easier |

## Open Questions

- **SNIP + shared weights (thesis experiment)**: SNIP's backward pass naturally accumulates gradient signal from both W→x and Wᵀ→x' paths for the shared parameter W in a single pass. The resulting s_j is a joint sensitivity score across both uses simultaneously — arguably the correct signal for which elements of a shared weight to prune. No modification to SNIP is needed; HaLViT just needs to run a standard backward pass with the shared weight tied. See [[sources/1810.02340]].
- **LTH + shared weights (thesis experiment)**: HaLViT's single shared parameter θ₀ must serve as a winning ticket initialization for all layers using W and Wᵀ simultaneously. IMP's weight rewind resets to this single θ₀; the sparsity mask m must be symmetric (M_ij = M_ji) to be valid for both W→x and Wᵀ→x' uses. Whether shared-weight networks have a harder or easier time winning the initialization lottery than unshared networks is an open empirical question — shared weights may be better initialized (more usage gradient signal) or worse (entangled initialization lottery across layers). See [[sources/1803.03635]].
- **HaLViT + Pruning**: HaLViT's Discussion explicitly calls for this composition. The key ambiguity: when Wkv is shared for both keys and values, pruning a row of Wkv removes both the key projection and its transposed value projection. The gradient signal for the pruning mask is entangled. See [[sources/halvit]].
- **Symmetric mask for W+Wᵀ sharing (thesis experiment)**: For HaLViT's W+Wᵀ structure, zeroing position (i,j) in W simultaneously zeroes (j,i) in the Wᵀ pathway. Enforcing a **symmetric sparsity mask** (M_ij = M_ji) makes the pruning pattern valid for both uses simultaneously. This is a constrained variant of SparseGPT — constrained to the symmetric mask space. Whether optimal symmetric masks are close to optimal unconstrained masks is an open question. See sparsegpt-method.
- **Joint SparseGPT+GPTQ for HaLViT**: The unified single-pass SparseGPT+GPTQ pipeline (Section 3.5 of [arxiv:2301.00774]) yields better compression than sequential application. Applied to a trained HaLViT model, this could yield 3-axis compression: weight sharing + pruning + quantization in one calibration pass.
- **LLM-Pruner dependency graph for HaLViT (thesis experiment)**: LLM-Pruner's dependency detection groups coupled structures, but it assumes each weight matrix has a single role. HaLViT's W+Wᵀ sharing violates this: row i of Wkv is used both as a key projection row (W→x) and as column i of the value transposed projection (Wᵀ→x'). A correct dependency graph must add a "W+Wᵀ coupling" constraint: pruning group i in W always forces pruning the same group in the Wᵀ pathway. This is a constrained version of LLM-Pruner recoverable without architectural changes. See [[sources/2305.11627]].
- At what sparsity level does accuracy collapse — and does weight sharing change this threshold?
- How do activation-based pruning signals transfer to ViT architectures vs. LLM transformers?
- **Overparameterization boundary**: OPT-175B and 66B actually improve at 50% sparsity. Where is the boundary for ViT models, and does HaLViT's weight sharing already exploit the same redundancy SparseGPT finds?

## Relevance to Project

HaLViT uses weight sharing within ViT layers. Composing this with structured pruning of attention heads could yield additive compression. The key risk is that weight sharing may prevent pruning from removing truly redundant weights — if weights are shared, pruning one connection affects all consumers of that weight.

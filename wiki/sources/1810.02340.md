## Problem

Existing pruning methods (Han et al., OBD, DNS) prune within an iterative optimization loop — train → prune → retrain → repeat. This requires pretraining, complex heuristic schedules, and many expensive prune-retrain cycles. Extending such methods to new architectures requires significant engineering. The paper asks: can we identify which connections to remove *before training even begins*, using only a single mini-batch?

## Method

**SNIP — Single-shot pruning at initialization** using a connection sensitivity criterion.

**Connection Sensitivity**: Introduce binary indicator variables c ∈ {0,1}^m that gate each connection. The sensitivity of connection j is the magnitude of the gradient of the loss with respect to c_j, evaluated at initialization:

```
g_j(w; D) = ∂L(c⊙w; D)/∂c_j |_{c=1} = ∂L/∂w_j · w_j    (by chain rule)
```

Normalized sensitivity score:
```
s_j = |g_j(w; D)| / Σ_k |g_k(w; D)|
```

Key properties of this criterion:
- **Scale-invariant**: measures influence on loss, not weight magnitude — unaffected by normalization layers
- **Data-dependent**: uses a mini-batch of actual training data, so captures task-specific importance
- **Initialization-compatible**: evaluated at Glorot (variance scaling) initialization, not a pretrained checkpoint
- **No pretraining required**: the indicator-variable gradient ∂L/∂c_j does not require the network to be near a minimum; it is informative even at initialization

**Algorithm:**
1. Initialize network with Glorot initialization
2. Forward + backward pass with a mini-batch to compute g_j for all connections
3. Compute normalized sensitivity scores s_j
4. Prune: retain top-κ connections (c_j = 1 iff s_j ≥ κ-th largest score)
5. Train the sparse masked network in the standard way

No additional hyperparameters. The only input beyond standard training is the desired sparsity level κ̄.

## Results

**LeNet-300-100 / LeNet-5-Caffe on MNIST:**
- LeNet-5-Caffe: negligible performance degradation at 90%+ sparsity
- LeNet-300-100: near-reference accuracy up to κ̄ = 90%; small degradation only at extreme κ̄
- Comparison at extreme sparsity: SNIP matches or beats LWC (Han et al.), DNS, LC, SWS, SVD, OBD, L-OBS across LeNet architectures — while requiring zero pretraining

**CIFAR-10 and Tiny-ImageNet:**
- Extremely sparse models with virtually no accuracy loss across VGG, ResNet, WRN, and LSTM architectures
- Consistent results without any architecture-specific modifications to the pruning procedure

**Interpretability experiment:** Varying the mini-batch used for computing sensitivity scores changes which connections are retained — confirming that SNIP selects task-relevant connections rather than performing blind structural pruning.

## Significance

SNIP sits at a distinct point in the pruning design space: before-training, single-shot, gradient-based. Three implications for the thesis:

1. **Pruning taxonomy**: SNIP establishes a third paradigm alongside IMP+rewind (LTH [arxiv:1803.03635]) and post-training one-shot (SparseGPT [arxiv:2301.00774]):
   - LTH: during-training, iterative, weight rewind, small models
   - SNIP: before-training, single-shot, gradient-based saliency, architecture-agnostic
   - SparseGPT: after-training, one-shot, Hessian-based, LLM-scale

2. **Application to HaLViT at initialization**: SNIP's sensitivity score g_j = ∂L/∂c_j ⊙ w_j for shared weight W would naturally accumulate gradients from both the W→x and Wᵀ→x' forward passes in one backward pass (since they share the same parameter). The resulting sensitivity score is thus automatically a joint measure across both uses — the correct signal for deciding which elements of a shared weight to prune. This is a strength over magnitude-based methods, which would need to manually combine signals from both paths.

3. **Practical edge**: Unlike LTH which requires full training + rewind cycles, SNIP adds essentially zero cost on top of a single training run. For HaLViT on ViT, this makes SNIP a viable pre-training compression step before QAT or PTQ.

## Contradicts / Supports

- **Contrasts** [[sources/1803.03635]] (LTH): LTH requires full pretraining + iterative rewind cycles; SNIP requires no pretraining at all — they are complementary points on the cost-accuracy tradeoff
- **Supports** lecun1990-obd (OBD): both use gradient/Hessian information to identify important weights; SNIP simplifies OBD by using first-order gradients w.r.t. indicator variables at init (no Hessian needed)
- **Contrasts** 1506.02626 (Han et al.): Han uses magnitude post-training; SNIP uses gradient sensitivity pre-training — SNIP achieves similar accuracy with far less compute
- **Contrasts** [[sources/2301.00774]] (SparseGPT): SparseGPT is post-training + Hessian; SNIP is pre-training + first-order gradient; SparseGPT scales to 175B, SNIP targets smaller training-time scenarios

## Problem

Post-training quantization methods (GPTQ, AWQ, SmoothQuant) hand-craft key quantization parameters — clipping ranges, migration strengths, scaling factors — leading to large accuracy drops at aggressive low-bit settings (W2A16, W3A16, W4A4). QAT achieves better accuracy but requires 100K samples and hundreds of GPU hours. The goal: achieve QAT-level accuracy at PTQ-level efficiency by making the key quantization parameters *learnable* while keeping the base weights frozen.

## Method

OmniQuant freezes the original FP16 weights and uses SGD to optimize only a small set of quantization parameters via block-wise quantization error minimization:

```
argmin_{Θ₁,Θ₂} ||F(W, X) − F(Q_w(W; Θ₁, Θ₂), Q_a(X; Θ₂))||    (Eq. 1)
```

where F is the transformer block function, Q_w and Q_a are weight and activation quantizers, Θ₁ and Θ₂ are the learnable quantization parameters. The block-wise objective allows sequential optimization: quantize one transformer block before moving to the next, with minimal GPU memory overhead.

### Component 1: Learnable Weight Clipping (LWC)

Standard PTQ uses fixed clipping ranges (min-max or percentile). OmniQuant replaces these with learnable per-channel clipping strengths γ, β ∈ [0, 1] (parameterized via sigmoid):

```
W_q = clamp(⌊W/h⌋ + z, 0, 2^N − 1)
h = (γ·max(W) − β·min(W)) / (2^N − 1)
z = −⌊β·min(W) / h⌋
```

When γ=1, β=1: degenerates to vanilla MinMax quantization (GPTQ/AWQ default). SGD optimizes γ and β to find the clipping threshold that minimizes block reconstruction error. The optimal threshold clips extreme values that create large quantization bins, making the remaining weight distribution easier to represent at low bit-width. Θ₁ = {γ, β}.

After optimization, the clipping threshold is fused into the quantized weights — **zero inference overhead**.

### Component 2: Learnable Equivalent Transformation (LET)

SmoothQuant migrates quantization difficulty from activations to weights via a mathematically equivalent transformation:

```
Y = XW + B = (X·diag(s)⁻¹)·(diag(s)·W) + B = X̂·Ŵ + B
```

SmoothQuant hand-crafts s using calibration statistics. OmniQuant learns s jointly with LWC via gradient descent.

For a linear layer, OmniQuant applies both channel-wise scaling and shifting:

```
Y = [(X − δ) ⊘ s] · [s ⊙ W] + [B + δW]      (Eq. 3)
    ≡ X̂ · Ŵ + B̂
```

where s ∈ ℝ^{C_in} and δ ∈ ℝ^{C_in} are per-channel learnable parameters. This equivalent transformation shifts quantization difficulty from activations (X is hard to quantize due to outlier channels) to weights (Ŵ = diag(s)·W now absorbs the scaling). Then LWC handles the weight clipping on Ŵ.

**Attention-specific LET**: The self-attention affinity matrix P = Softmax(QKᵀ) is also quantized. OmniQuant applies:

```
P = Softmax(QKᵀ) = Softmax((Q ⊘ s_a)(s_a ⊙ Kᵀ))      (Eq. 5)
```

The per-channel attention scaling factor s_a ∈ ℝ^{C_out} is absorbed into the Q and K linear projection weights — no overhead at inference. The V projection is excluded: its distribution is already adjusted by the inverse transformation of the output projection layer.

Θ₂ = {δ, s, s_a}.

**Note**: LET is not applied to the second linear layer of FFN in LLaMA because the high sparsity of features after the non-linear activation (SiLU) leads to unstable gradients.

### Training Details

- **Optimizer**: AdamW, zero weight decay
- **Learning rates**: 5e-3 for LWC (Θ₁), 1e-2 for LET (Θ₂)
- **Calibration**: 128 randomly selected 2048-token segments from WikiText2
- **Epochs**: 20 (40 for W2A16 which needs more optimization)
- **Hardware**: Single NVIDIA A100-40G GPU
- **Runtime**: 1–16 hours for LLaMA-2 7B–70B

After training, all learned parameters (γ, β, s, δ, s_a) are absorbed ("fused") into the quantized weights and quantization statistics. The final quantized model has **zero extra parameters** compared to standard PTQ.

## Results

| W4A16 | LLaMA-13B | 5.24 | 5.17 | 5.14 | **5.10** |
| W3A16 | LLaMA-7B | 7.01 | 6.55 | 6.46 | **6.49** |
| W3A16g128 | LLaMA-7B | 6.66 | 6.13 | 6.24 | **6.15** |
| W2A16 | LLaMA-7B | 1.9e3 | 22.10 | 2.6e5 | **9.72** |
| W2A16g64 | LLaMA-7B | 1.9e3 | 7.34 | 2.5e5 | **8.90** |
| W2A16 | LLaMA-13B | — | 10.06 | — | **7.93** |

| W2A16 | LLaMA-2-70B | 2.1e3 | 2.1e3 | NaN | **10.31** |

**Key results**: At W2A16, AWQ completely fails (2.6e5 PPL) and GPTQ degrades severely (22.10). OmniQuant holds at **9.72** — making W2A16 practical for the first time without QuIP's incoherence processing. At W4A16, OmniQuant is best across all sizes.

### Real-Device Deployment

- **Memory reduction**: W4A4 requires ~4× less memory than FP16
- **Inference speedup**: W4A4 enables real on-device speedup via integer arithmetic units
- OmniQuant implements deployment-friendly per-token activation quantization (not per-tensor, which degrades quality at W4A4)

## Significance

- **Bridges the QAT/PTQ gap**: achieves QAT-level accuracy at PTQ-level cost (128 samples vs 100K, 1.6h vs 90h) by making only quantization parameters learnable — not the model weights
- **Learnable equivalent transformation generalizes SmoothQuant**: LET subsumes SmoothQuant (which hand-crafts s) as a special case; gradient optimization finds the scale factor that actually minimizes block reconstruction error, not a heuristic approximation
- **First practical W4A4 for LLMs**: prior methods fail catastrophically at W4A4 (weight AND activation at 4-bit simultaneously); OmniQuant's learnable migration makes this viable
- **BESA::pruning = OmniQuant::quantization** (same philosophy, same lab — OpenGVLab/Ping Luo): both replace hand-crafted hyperparameters (sparsity rates / quantization thresholds) with differentiable optimization; both use block-wise reconstruction as the objective. The two methods compose directly (BESA Section 4.4 uses OmniQuant for joint pruning+quantization)
- **For HaLViT**: OmniQuant's block-wise objective (Eq. 1) already integrates over all operations within the transformer block. In HaLViT, both the W→x and Wᵀ→x' paths fall within the same attention or FFN block. The block reconstruction loss therefore automatically sees both paths — LWC clipping thresholds and LET scale factors are learned to minimize error across both uses of the shared W tensor simultaneously. **OmniQuant is the most naturally compatible quantization method for HaLViT's shared weights**, requiring no modification to handle the joint calibration problem.

## Contradicts / Supports

- **Extends** 2211.10438 (SmoothQuant): LET is SmoothQuant with learnable migration strength; both use the same mathematically equivalent transformation Y=XW=(X/s)(sW), but SmoothQuant hand-crafts s while OmniQuant learns it — a strict generalization
- **Improves upon** [[sources/2210.17323]] (GPTQ): better at W3A16, W2A16, and W4A4; block-wise error minimization is more flexible than GPTQ's column-sequential row-wise reconstruction
- **Orthogonal to** [[sources/2307.13304]] (QuIP): QuIP applies global incoherence via random rotations; OmniQuant applies learnable local equivalent transformations; both go beyond GPTQ at low bit-widths through different mechanisms — they could be combined
- **Supports** [[sources/2402.16880]] (BESA) composability: BESA Section 4.4 directly applies OmniQuant for joint pruning+quantization, achieving better results than sequential compression

## Problem

Magnitude pruning collapses on LLMs beyond 10–30% sparsity. Accurate one-shot methods (AdaPrune, OBC) require inverting a different Hessian H_{M_i}^{-1} for each row i of weight matrix W, costing O(d_row × d_col³) — extrapolating AdaPrune's 4.3h on a 1.3B model gives several hundred hours for 175B. No accurate post-training pruning at the scale of GPT-175B or BLOOM-176B existed.

## Method

SparseGPT reformulates the layer-wise pruning problem as approximate sparse regression, then solves it via **Hessian Synchronization** — sharing a single sequence of inverse Hessians across all rows.

**Layer-wise pruning objective** (for each layer ℓ):
```
argmin_{mask M, W_hat} ||W_ℓ X_ℓ - (M_ℓ ⊙ W_hat_ℓ) X_ℓ||₂²
```

### Why the exact solution is expensive

Optimal reconstruction for row i requires inverting H_{M_i}^{-1} where H_{M_i} = X_{M_i} X_{M_i}^T — the Hessian restricted to non-pruned features for row i. Since masks differ per row, each requires a separate O(d_col³) inversion: total O(d_row × d_col³).

### Hessian Synchronization (key contribution)

Define a sequence of index subsets U_j removing one element at a time:
```
U_{j+1} = U_j - {j},   U_1 = {1, ..., d_col}
```
Corresponding inverse Hessians (H_{U_j})^{-1} = (XX^T_{U_j})^{-1} can be computed recursively via one step of Gaussian elimination:
```
(H_{U_{j+1}})^{-1} = (B - (1/[B]_11) · B_{:,1} B_{1,:})_{2:,2:}
```
at O(d_col²) per step, total O(d_col³). This sequence is SHARED across all rows — the approximation error is that each row uses only a subset of available weights for compensation. In practice the approximation is ~20% worse than exact reconstruction on early attention layers, ~10% on FC layers.

### Adaptive Mask Selection

Instead of selecting the pruning mask by magnitude, SparseGPT iterates through B_s = 128 column blocks, selects the top-p% weights within each block that incur the minimum OBS reconstruction error (using diagonal H^{-1}_{jj} values). This allows non-uniform sparsity distribution across columns — critical for LLMs which have highly non-uniform outlier dimensions.

### Extension to Semi-Structured Sparsity

For 2:4 patterns (exactly 2 zeros per 4 consecutive weights), set B_s = m = 4. The mask for each group of 4 is selected by choosing the 2 weights with lowest OBS error. Supported in hardware by NVIDIA Ampere's sparse tensor cores (2× theoretical speedup for matmul).

### Joint Sparsification + Quantization (one pass)

SparseGPT and GPTQ share the column-wise greedy framework with the same Cholesky-based Hessian updates. They can be merged into a single compression pass: pruned weights are also quantized, and later decisions account for both effects jointly. Error term (Eq. 7):
```
E_{:,j-i} ← (W_{:,j} - M_{:,j} · quant(W_{:,j})) / [H^{-1}]_jj
```
This is the theoretically correct way to combine pruning and quantization — unlike applying them sequentially, joint decisions account for the interaction between rounding errors and pruning errors.

**Calibration**: 128 randomly chosen 2048-token segments from C4. Same setup as GPTQ. ~4.5 hours on a single A100 for 175B models.

### Practical speedups

**CPU (DeepSparse, OPT-2.7B, unstructured, Table 7)**:
- 40% sparsity: 1.57×
- 50% sparsity: **1.82×**
- 60% sparsity: **2.16×**

**GPU 2:4 semi-structured (Ampere CUTLASS, OPT-175B layer shapes, Table 8)**:
- Q/K/V/Out: 2.84ms → 1.59ms (**1.79×**)
- FC1: 10.26ms → 6.15ms (**1.67×**)
- FC2: 10.23ms → 6.64ms (**1.54×**)

### Layer sensitivity (Figure 7 / partial 2:4)

Later layers are more sensitive than earlier ones across both OPT and BLOOM. Skipping the final 1/3 of layers from 2:4 sparsification gives the best accuracy. Implication: if pruning is applied to weight-shared models, shared weights used in later layers carry higher risk and may need to be excluded or given lower sparsity targets.

## Significance

- **First accurate one-shot pruning for 100B+ LLMs** — 50% of OPT-175B weights can be dropped in 4.5h on a single A100, with zero perplexity increase (slight improvement).
- **More than 100 billion weights discarded from OPT-175B + BLOOM-176B** with negligible accuracy impact.
- **Proves overparameterization → compressibility**: at 66B and 175B parameters, pruning to 50% *improves* accuracy — dense models at this scale are provably over-specified.
- **Joint SparseGPT + GPTQ = superior to either alone**: 50% sparse + 4-bit beats 3-bit GPTQ at equivalent storage. Single-pass compression is the practical recommendation for LLM deployment.
- **Composability with HaLViT**: SparseGPT is post-training, calibration-only. It can be applied to a trained HaLViT model. The structural challenge: HaLViT's W+Wᵀ sharing means zeroing position (i,j) in W simultaneously zeroes position (j,i) in the Wᵀ pathway. A **symmetric mask** (M_ij = M_ji enforced) makes the sparsity pattern jointly valid for both W and Wᵀ — a constrained variant of SparseGPT. Whether symmetric masks are near-optimal for the W+Wᵀ operator is an open research question with direct thesis relevance.

## Contradicts / Supports

- **Supports** [[sources/halvit]] on composability: SparseGPT is a post-training, calibration-only method — compatible with the same pipeline as GPTQ. No retraining is needed, so weight-sharing structure learned during training is preserved through compression.
- **Supports** [[sources/2210.17323]] (GPTQ): both share the same column-wise Cholesky framework; their merger into a single pass (Section 3.5) is the recommended approach for joint compression. This unified SparseGPT+GPTQ pipeline is directly relevant for applying to HaLViT.
- **Tension with** [[sources/halvit]] on shared-weight pruning: SparseGPT's OBS Hessian H = XX^T is derived from the single forward path W → output. For W+Wᵀ sharing, the correct Hessian must also account for the Wᵀ pathway. Uncorrected, the pruning mask will be suboptimal for the transposed use — analogous to GPTQ's single-path limitation. See gptq-method.

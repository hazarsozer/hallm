## Problem

HW-EvRSNAS [arxiv:2311.03923] solves a single-objective HW-NAS problem. If multiple hardware cost constraints are needed (e.g., find optimal architectures for six different edge devices), it must be re-run once per constraint — multiplying the search cost. Naive two-objective conversion (maximize RMI, minimize hardware cost) fails because high-performing architectures typically have high hardware cost, directly contradicting the second objective — the search collapses to low-cost, low-accuracy architectures.

## Method

**MO-HDNAS** (Multi-Objective Hardware-aware NAS with Hardware Cost Diversity) extends HW-EvRSNAS with three objectives optimized jointly using NSGA-II (Non-dominated Sorting Genetic Algorithm II — a standard Pareto multi-objective EA):

1. **Maximize RMI** (Representation Mutual Information w.r.t. reference model) — proxy for accuracy
2. **Minimize hardware cost** (latency on target device)
3. **Maximize hardware cost diversity** — the novel third objective; encourages the population of candidates to spread across diverse hardware cost values, allowing the search to also explore higher-cost (and potentially higher-accuracy) architectures that would otherwise be suppressed by objective 2 alone

Result: a single run produces a full Pareto-optimal set of architectures with diverse hardware cost profiles, covering all target devices simultaneously.

## Results

- Finds Pareto-optimal architecture sets across six edge devices in a single run
- Outperforms naive two-objective conversion (which collapses to low-cost architectures)
- Validated on NAS-Bench-201 search space (CIFAR-10)

## Significance

MO-HDNAS closes the gap between single-objective HW-NAS (requires one run per hardware constraint) and true multi-device deployment (find one set of architectures covering all devices). The hardware cost diversity objective is the key insight — without it, multi-objective NAS degenerates. Extension of HW-EvRSNAS [arxiv:2311.03923] from the same Luxembourg group.

For HaLViT: the same diversity-aware multi-objective framework could be applied to a NAS over weight-sharing configurations — objective 1: RMI to a reference HaLViT, objective 2: parameter count (compression ratio), objective 3: sharing topology diversity (different layer groupings). This would find a Pareto front of sharing configurations rather than requiring separate searches for each compression target.

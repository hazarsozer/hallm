## Problem

OPT-175B requires 326GB in FP16 — beyond single-GPU capacity. Deploying LLMs for inference requires either expensive multi-GPU setups or compression. Existing post-training quantization (PTQ) methods only remain accurate down to 8-bit for large models. Training-based methods require full retraining, infeasible at 175B scale. The question: can PTQ achieve 3–4 bit compression of 100B+ parameter models without accuracy collapse?

## Method

GPTQ extends **Optimal Brain Quantization (OBQ)** — a second-order PTQ method that quantizes one weight at a time while adjusting remaining weights to compensate for the rounding error. OBQ is O(d_row × d_col³): too slow for LLMs (OPT-175B would take weeks). GPTQ makes three algorithmic modifications:

### Step 1: Arbitrary Order Insight

OBQ quantizes weights in greedy order (minimum error first). GPTQ observes: on large, heavily-overparameterized models, any fixed quantization order yields similar final squared error. Using a **fixed column-by-column order** for all rows means the inverse Hessian H_F^{-1} depends only on layer inputs X, not on weight values — so it is identical for all rows and can be computed once. Runtime reduction: O(d_row × d_col³) → O(max{d_row × d_col², d_col³}).

### Step 2: Lazy Batch Updates

The final rounding decision for column i only depends on updates to column i; later column updates are irrelevant at that point. GPTQ processes **B=128 columns at a time**: within each block, apply the local algorithm; then flush global updates to H^{-1} and W at the block boundary. This achieves an order-of-magnitude improvement in GPU memory throughput.

### Step 3: Cholesky Reformulation

At LLM scale, accumulated numerical errors cause H_F^{-1} to become indefinite, corrupting weight updates. GPTQ precomputes all needed rows of H^{-1} **upfront via Cholesky decomposition**, eliminating repeated matrix inversions. Robust for models with billions of parameters; adds a speedup bonus from optimized LAPACK kernels.

**Full Algorithm (Algorithm 1)**:
```
Input: W, H^{-1} = (2XX^T + λI)^{-1}
H^{-1} ← Cholesky(H^{-1})^T
For i = 0, B, 2B, ... do:
  For j = i, ..., i+B-1:
    Q[:,j] ← quant(W[:,j])           // quantize column
    E[:,j-i] ← (W[:,j] - Q[:,j]) / [H^{-1}]_jj  // quantization error
    W[:,j:(i+B)] -= E[:,j-i] · H^{-1}_j,j:(i+B) // update remaining in block
  W[:,(i+B):] -= E · H^{-1}_i:(i+B),(i+B):      // update all remaining
```

**Calibration**: 128 random 2048-token segments from C4 (random web text). No task-specific data. Fully zero-shot. Runs on a single A100 80GB.

**Grouping**: Independent quantization of groups of g consecutive weights. Groups of g=128 bring small accuracy gains (~0.1–0.2 PPL) at the cost of ~0.15 extra bits per weight. Compatible with any quantization grid.

## Significance

- **First PTQ method achieving near-lossless 3–4 bit compression of 100B+ LLMs** — prior PTQ only held accuracy at 8-bit for large models; GPTQ pushed the frontier to 3-bit.
- **Practical single-GPU inference for 175B models** — what previously required 5×80GB A100 GPUs now runs on 1.
- **3.24–4.53× throughput gain** — real latency improvement for single-token generation, not just theoretical compression.
- **Extreme quantization viability** — 2-bit grouping with only 0.11 PPL loss on 175B opens the door to sub-3-bit deployment.
- **Post-training, zero retraining** — 4-hour calibration on C4, no gradient computation, no task labels.
- **Composability with HaLViT** — GPTQ is the most relevant quantization method to attempt on HaLViT's shared weights. The central open question is how to adapt the Hessian construction to account for weight-sharing paths (see Contradicts/Open Questions below).

## Contradicts / Supports

- **Supports** [[sources/halvit]] composability claim: GPTQ works post-training with only calibration data — exactly the regime in which it would be applied to a trained HaLViT model.
- **Tension with** [[sources/halvit]] and [[sources/1909.11942]] on shared weights: GPTQ's Hessian H = 2XX^T is derived from a single layer's input, calibrating compensation for one forward-path W → output. When W is shared as W and Wᵀ (HaLViT) or across multiple layers (ALBERT/Basis Sharing), quantizing W affects multiple distinct computational paths. Standard GPTQ's single-path Hessian underestimates the true error sensitivity of a shared weight, potentially producing worse quantization than expected. A joint Hessian H_joint = 2(X₁X₁^T + X₂X₂^T + ...) over all paths using the shared weight would be required for optimal compensation — an open research direction.
- **Extends** OBQ (Frantar & Alistarh 2022): GPTQ's three modifications (arbitrary order, lazy batching, Cholesky) are the key engineering contributions that make second-order PTQ tractable at LLM scale.

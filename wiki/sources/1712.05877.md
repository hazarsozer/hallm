## Problem

Prior quantization methods suffered from two gaps: (1) they evaluated on over-parameterized baselines (AlexNet, VGG) where compression is trivially easy, and (2) they did not deliver hardware-verified latency improvements on real mobile hardware — weight-only quantization saves storage but not compute. The field lacked a scheme that was simultaneously hardware-efficient, accuracy-preserving, and benchmarked on already-efficient architectures (MobileNets).

## Method

**Integer-only arithmetic quantization** — a unified scheme for quantizing both weights and activations to INT8, enabling inference entirely with integer arithmetic (no floating-point required):

**Quantization scheme** (affine/asymmetric):
```
r = S · (q − Z)
```
- `r`: real value, `q`: quantized integer, `S`: scale (float32), `Z`: zero-point (integer)
- Weights → INT8; activations → INT8; bias vectors → INT32
- Matrix multiply: 8-bit × 8-bit operands → 32-bit accumulator, then requantize to INT8
- Multiplier `M = S₁S₂/S₃` decomposed as `M₀ × 2⁻ⁿ` (M₀ a fixed-point value); enables pure integer multiply-shift with no floats at runtime

**Quantization-aware training (QAT)** — simulates quantization during training:
- Insert "fake quant" nodes after weights and activations that quantize-then-dequantize in the forward pass
- Gradients pass through via straight-through estimator (STE)
- Batch normalization folded into preceding conv/FC layer before quantizing weights
- Training computes in FP32 but the forward pass mimics INT8 rounding — the model learns to be robust to quantization error

**ReLU6 insight**: ReLU6 bounds activations to [0, 6], providing a natural fixed range that is easier to quantize at high precision than unbounded ReLU. Quantized models with ReLU6 show less accuracy degradation than ReLU variants.

## Results

**ResNets on ImageNet:**
- INT8 quantized ResNets within ~2% top-1 accuracy of FP32 counterparts across all depths
- Outperforms FGQ (2-bit weights) and matches INQ (5-bit weights/float activations) while additionally delivering runtime speedup

**Inception v3:**
- 8-bit: near-FP32 accuracy
- 7-bit: close to 8-bit; ReLU6 nonlinearity reduces degradation vs. ReLU

**MobileNets on ImageNet (Qualcomm Snapdragon 835 LITTLE cores):**
- ~2× latency reduction versus float MobileNets at the same accuracy level
- Quantized INT8 model beats float model at same latency budget

**COCO object detection (MobileNet SSD):**
- 8-bit quantized vs. float: near-identical mAP with ~2× latency improvement

**Face detection:**
- ~2% average precision drop; ~2× latency reduction
- 25% face detector achieves real-time at ~36 fps on Snapdragon 835

## Significance

This paper established the **canonical INT8 quantization scheme** adopted by TensorFlow Lite and is the direct ancestor of all mobile edge deployment pipelines. Three contributions stand out for the thesis:

1. **QAT vs. PTQ distinction**: This is the founding QAT paper for efficient inference. GPTQ and AWQ are PTQ; this paper demonstrates that QAT achieves higher accuracy than PTQ at the same bit-width, at the cost of retraining. The tradeoff is central for HaLViT: PTQ can be applied post-hoc; QAT requires reintegrating quantization into HaLViT's training loop.

2. **Hardware-verified results**: The only paper in the wiki to report actual ARM CPU latency numbers for quantized models. Establishes the 2× latency reduction as a reliable baseline for INT8 on mobile.

3. **Composability with weight sharing**: INT8 QAT is a training-time modification compatible with other training-time techniques (unlike PTQ which is post-hoc). This means QAT + HaLViT weight sharing could co-exist in a single training run — though fake quant nodes would need to be applied to the single shared weight W, and the STE gradient for both W→x and Wᵀ→x' paths must be combined correctly.

## Contradicts / Supports

- **Supports** [[sources/2210.17323]] (GPTQ): both target low-bit quantization; Jacob et al. uses QAT while GPTQ uses PTQ — complementary approaches
- **Contrasts** 2310.11453 (BitNet): BitNet goes to 1-bit via training from scratch; this paper achieves near-lossless INT8 via QAT fine-tuning — different points on the bit-width/retraining tradeoff curve
- **Supports** 1510.00149 (Deep Compression): Deep Compression's k-means codebook quantization also uses retraining (centroid fine-tuning); this paper makes the case more rigorously with hardware verification

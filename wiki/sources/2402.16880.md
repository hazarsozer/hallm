## Problem

SparseGPT and Wanda are the state-of-the-art LLM pruning methods, but share two structural weaknesses:

1. **Layer-wise error accumulation**: Both minimize the reconstruction error of each layer independently. As shown in Figure 1(a), the accumulated error across the full model is significantly larger than what layer-wise metrics predict — errors compound. A block-level error objective would be more accurate.

2. **Uniform sparsity rate**: Both apply a fixed, manually-chosen sparsity rate to all layers equally. Figure 1(b) shows that layers contribute very unequally to model performance — some layers tolerate 60%+ sparsity; others collapse at 20%. A method that discovers optimal per-layer rates automatically would improve both accuracy and remove the need for hyperparameter tuning.

## Method

BESA (Blockwise Parameter-Efficient Sparsity Allocation) addresses both weaknesses with a unified differentiable framework.

### Block-Wise Pruning Objective

For each transformer block with weight matrices W = {W^l} and corresponding learnable binary masks M = {M^l}, BESA minimizes:

```
argmin_M L^block = ||F(W, X) − F(W ⊙ M, X)||²_F + λ · (1/T^b · Σ_{M∈M} k(M) − α̂)²   (Eq. 1)
```

where:
- F(W, X) is the full-precision block output
- F(W ⊙ M, X) is the pruned block output
- L^{recon} = ||F(W,X) − F(W⊙M,X)||²_F minimizes block reconstruction error
- L^{sparse} = λ(1/T^b · Σ k(M) − α̂)² encourages the pruned model to meet the target sparsity α̂
- T^b is the total number of parameters in the block; k(M) returns the count of zeros in mask M

The block-wise objective accounts for **interactions between layers** within the same block — the attention output affects FFN input, so pruning decisions in attention are evaluated jointly with their effect on FFN reconstruction.

### Parameter-Efficient Sparsity Learning

Directly learning a binary mask M for all weights is a huge discrete search space. BESA uses a **parameter-efficient proxy**:

**Weight Sorting** (Eq. 2): Sort each row by Wanda-style importance score:
```
δ_{i,j} = |W_{i,j}| · ||x_{:,j}||₂,    W_ij = Sort(W_{i,j} | δ_{i,j})
```

Sorting is done once per block and is invariant to the pruning procedure.

**Layer Sparsity Parameterization** (Eq. 3): Instead of learning a separate rate per weight, BESA parameterizes each layer's sparsity as a convex combination of D=100 **candidate pruning rates** {p_d}^D_{d=1}:

```
α = Σ_{d=1}^D β_d p_d,     β = [β₁,...,β_D]^T ∈ Δ^{D-1}   (simplex)
```

β is the only learned parameter per layer — D scalar values.

**Pruning Probability** (Eq. 4): Given the sorted weight importance, the probability that weight W_{i,j} (the j̃-th most important in row i) is pruned:

```
P(W_{i,j}) = Σ_{d=k+1}^D β_d    if  C_out·p_k ≤ j̃ < C_out·p_{k+1}
```

Less important weights (lower j̃) have higher pruning probability.

**Binary Mask Generation** (Eq. 5):
```
M_{i,j} = { 0  if P(M_{i,j}) ≥ α    (pruned)
           { 1  otherwise             (kept)
```

**Gradient via STE** (Eq. 6): The discrete mask M is non-differentiable; BESA uses the Straight-Through Estimator:
```
∂L^block/∂α = p_d · Σ ∂L^block/∂β_d · ∂β_d/∂α
```

This makes the sparsity α differentiable through β, enabling standard gradient descent to simultaneously optimize pruning masks and sparsity allocation.

**Extra parameters**: 2.10% of a transformer block (row-wise, D=100) in the standard setting; 0.0003% in the lightweight layer-wise setting.

### Joint Optimization with Quantization

BESA's block-wise reconstruction framework extends naturally to **joint pruning + quantization** (Section 3.3). Quantize W first:

```
Q(W) = clamp(⌊W/h⌋ + z),    h = (γ₁·max(W) − γ₀·min(W)) / (2^N − 1)   (Eq. 7)
```

where γ₀, γ₁ ∈ [0,1] are learnable clipping strengths (same as OmniQuant's LWC). Then apply BESA to the quantized weights Q(W) ⊙ M. The combination coefficients {β_d} and quantization clipping thresholds {γ₀, γ₁} are optimized jointly.

## Results

### WikiText2 PPL — 50% Unstructured Sparsity (Table 1, LLaMA families)

| Model | Dense | SparseGPT | Wanda | **BESA** |
|-------|-------|----------|-------|---------|
| LLaMA1-7B | 5.68 | 7.22 | 7.26 | **6.86** |
| LLaMA1-13B | 5.09 | 6.21 | 6.15 | **5.92** |
| LLaMA1-30B | 4.10 | 5.33 | 5.25 | **5.00** |
| LLaMA1-65B | 3.53 | 4.60 | 5.25 | **4.33** |
| LLaMA2-7B | 5.47 | 6.99 | 6.92 | **6.60** |
| LLaMA2-13B | 4.88 | 6.02 | 5.97 | **5.75** |
| LLaMA2-70B | 3.31 | 4.25 | 4.22 | **4.09** |

BESA outperforms SparseGPT and Wanda consistently across all scales. LLaMA2-70B: **+0.16 PPL** better than SparseGPT.

### Zero-Shot Tasks — 50% Sparsity (Table 2, average of 6 tasks)

| Model | Dense | SparseGPT | Wanda | **BESA** |
|-------|-------|----------|-------|---------|
| LLaMA1-7B | 66.31% | 63.12% | 61.81% | **63.13%** |
| LLaMA1-13B | 68.91% | 65.98% | 66.49% | **67.43%** |
| LLaMA1-65B | 73.71% | 72.63% | 72.82% | **73.73%** |
| LLaMA2-70B | 74.30% | 73.69% | 72.88% | **73.85%** |

LLaMA1-65B BESA (73.73%) **matches dense baseline** (73.71%) at 50% sparsity — overparameterization effect at scale.

### Joint Pruning + Quantization (Section 4.4, LLaMA1-7/13B, 30B)

BESA + OmniQuant 4-bit outperforms Wanda + quantization (post-pruning quantization) on all models, confirming that **joint optimization is superior to sequential application**.

### Efficiency

- **Runtime**: full 50% sparsity pruning of LLaMA-65B in **~4.5 hours on a single A100-80GB**
- **Single GPU throughout**: no multi-GPU requirement for models up to 65B
- **Verification on ViTCoD hardware simulator**: speedup estimates consistent with real-world sparse inference

## Significance

- **First differentiable LLM pruning algorithm**: BESA is to pruning what OmniQuant is to quantization — it makes the key hyperparameter (sparsity rate per layer) learnable via gradient descent, eliminating the largest source of manual tuning in LLM compression
- **Block-level error objective**: the conceptual insight that layer-wise error accumulation causes suboptimal pruning is confirmed empirically (Figure 1a) and resolved architecturally (Eq. 1 block objective)
- **Wanda criterion reused**: BESA adopts Wanda's δ_{i,j} = |W_{i,j}|·||x_{:,j}||₂ for weight sorting, then goes further by making the threshold learnable rather than fixed — BESA strictly generalizes Wanda
- **From the same group as OmniQuant** (Ping Luo, OpenGVLab, Shanghai AI Lab): the two methods compose directly (Section 4.4 joint compression); BESA provides the pruning component, OmniQuant provides the quantization component of a unified differentiable compression pipeline
- **For HaLViT**: BESA's block-level reconstruction loss (Eq. 1) integrates over all operations within the transformer block simultaneously. In HaLViT, both the W→x (key/forward projection) and Wᵀ→x' (value/output projection) paths execute within the same attention or FFN block. The block reconstruction objective therefore naturally accounts for both uses of shared W — pruning decisions are evaluated by their combined effect on block output accuracy. **No modification is required to handle HaLViT's W+Wᵀ coupling**. BESA is the most principled pruning method for HaLViT.

## Contradicts / Supports

- **Improves upon** [[sources/2301.00774]] (SparseGPT): block-wise objective eliminates error accumulation; differentiable sparsity eliminates fixed-rate limitation; lower PPL across all tested models
- **Improves upon** [[sources/2306.11695]] (Wanda): uses Wanda's importance score but learns the threshold rather than applying a fixed rate; block-level feedback makes the pruning globally consistent
- **Extends** [[sources/2308.13137]] (OmniQuant) philosophy: both make hand-crafted hyperparameters learnable via differentiable optimization; composing the two methods (Section 4.4) achieves the best joint compression results
- **Extends** [[sources/2305.11627]] (LLM-Pruner): addresses LLM-Pruner's two main limitations (layer-wise accumulation, fixed sparsity rate); both use block-level objectives as the right scope for LLM pruning decisions

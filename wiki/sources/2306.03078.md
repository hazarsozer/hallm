## Problem

3–4 bit PTQ methods (GPTQ, RTN) cause moderate-to-high accuracy losses, especially in the 1–10B parameter range most relevant for edge deployment. The root cause: LLM weight matrices contain *outlier weights* that induce disproportionately large quantization errors, and these outliers vary by layer depth, weight type (attention vs MLP), and position within the matrix. Existing methods treat all weights uniformly and cannot protect outliers without expensive mixed-precision hardware paths.

## Method

SpQR introduces a **two-step hybrid compressed format**:

### Step 1: Sensitivity Analysis and Outlier Detection

SpQR uses the OBS (Optimal Brain Surgeon) sensitivity measure to identify outlier weights. The sensitivity of weight w_ij is defined as the minimum squared difference between the original layer output and any output where w_ij is quantized:

```
s_ij = min_{W'} ||WX - W'X||₂²   s.t.  w'_ij = quant(w_ij)
     = (w_ij - quant(w_ij))² / 2(XX^T)⁻¹_jj
```

This is computed efficiently during GPTQ's column-sequential processing — the inverse Hessian (XX^T)⁻¹ is already available. A weight is classified as an outlier if keeping it in 16-bit reduces the error in Eq. above by at least τ (sensitivity threshold). The algorithm targets ~1% of weights as outliers.

**Four empirically-observed outlier patterns** (Figure 2, LLaMA-65B attention layers):
- **Row outliers**: High-sensitivity regions spanning full or partial rows, concentrated in specific output neurons. Some correspond to attention heads.
- **Column outliers**: High sensitivity across all rows for specific input dimensions — the same "outlier feature" phenomenon as LLM.int8(), but observed in weight space rather than activation space.
- **Sensitive attention heads**: Regular stripes of width 128 (one head's worth of weights) with high sensitivity. Present in Q/K layers (horizontal stripes), output projection (vertical stripes), absent in value layers and MLP.
- **Rotary embedding pattern**: Periodic sensitivity pattern with period 64 in models using RoPE. Low-frequency sinusoidal dimensions are more sensitive than high-frequency counterparts.

### Step 2: Bilevel Quantization for Non-Outlier Weights

Non-outlier weights (≥99% of all weights) are stored in a two-level compressed format:
- **First level**: Groups of β₁=8–32 consecutive weights quantized to b_w=3 bits with per-group scales and zero-points
- **Second level**: The quantization statistics themselves (scales, zero-points) from β₂=16 groups are quantized together to 3 bits, reducing metadata overhead

This runs counter to the conventional wisdom that group sizes should be large (e.g., g=128 in GPTQ). Small groups are necessary because outlier patterns change abruptly between groups; SpQR compensates for the metadata overhead by also quantizing the metadata.

### Outlier Storage

Outliers are stored as a **sparse matrix in compressed sparse row (CSR) format**. Each outlier stores the 16-bit weight value and the 16-bit column index. For each row, a 32-bit running count of outliers enables efficient GPU inference. Average storage cost: ~32 bits per outlier weight.

**Full Algorithm (Algorithm 1)**:
```
SpQRQuantize(W, X, b, β₁, β₂, τ, λ):
  E := L2 error matrix
  H := 2XX^T   (L2 error Hessian)
  H^uc := Cholesky(H + λI)^{-1}
  O := ∅   (outlier set)
  for i = 0, β₁, 2β₁, ... n:
    detect outliers in W[:,i:i+β₁] via sensitivity threshold τ
    fit bilevel quantization statistics (β₁, β₂ group sizes)
    quantize W[:,i:i+β₁] excluding outliers
    propagate error to remaining columns
  return quantized weights Q, quantization statistics, sparse outlier matrix W_sparse
```

### GPU Inference Algorithm

SpQR uses the memory-bandwidth-bound structure of LLM inference: autoregressive generation loads weights once per token. The inference kernel:
1. Divides the weight matrix into equally-sized thread blocks
2. Each GPU core loads a slice of outliers into shared memory (SRAM)
3. Each GPU core determines whether local weights are outlier or not
4. Loads the appropriate weights and performs matrix multiplication

Uses CSR sparse format for outlier handling; achieves better load balancing than standard PyTorch sparse operations.

## Results

### LLaMA 7/13/30/65B — WikiText2 PPL (3–4 bit, from paper Figure 1 and Table)

| Model | FP16 | GPTQ 4-bit | SpQR 4-bit | GPTQ 3-bit | SpQR 3-bit |
|-------|------|-----------|-----------|-----------|-----------|
| LLaMA-7B | 5.68 | 6.29 | **5.79** | 9.55 | **6.32** |
| LLaMA-13B | 5.09 | 5.53 | **5.22** | 7.55 | **5.60** |
| LLaMA-30B | 4.10 | 4.58 | — | 5.94 | — |
| LLaMA-65B | 3.53 | 3.84 | — | 4.56 | — |

At 3-bit, SpQR reduces perplexity gap from FP16 by >50% vs GPTQ for 7B and 13B models. SpQR achieves **<1% relative PPL loss** across all tested sizes at 3-4 bit.

### Hardware Deployment

- **LLaMA-33B on a single 24GB consumer GPU** (RTX 3090 / RTX 4090): possible at SpQR 3-4 bit where GPTQ 4-bit still requires multi-GPU setup
- **Compression ratio**: ~3.4× memory footprint reduction vs FP16
- **Inference speedup**: 20–30% faster generation than FP16 inference despite added complexity of sparse + quantized decoding
- **Storage**: at b_w=b_q=3, B_W=B_q=16 per group: 3-bit weights + 3-bit quantized scales + 16-bit outlier store ≈ 3.4 effective bits per weight

### Sensitivity Analysis Ablation

- **Uniform quantization without SpQR**: 4% LM loss increase on LLaMA-7B at 4-bit
- **SpQR without outlier protection** (bilevel quant only): still 2× better than GPTQ due to small groups
- **SpQR with outlier protection** (full method): <1% LM loss — outliers provide the final recovery
- **Layer depth effect**: deeper layers have more sensitive outliers; quantizing only the last 1/3 of layers with SpQR (rest with GPTQ) already provides significant improvement

## Significance

- **First near-lossless 3-4 bit PTQ across all LLM scales, including the 1-10B range** — this is the regime where GPTQ fails most severely and where edge deployment targets (7B models) live
- **Generalized outlier insight**: LLM.int8() discovered outliers in activations (input features); SpQR proves the same phenomenon exists in the weights, mapped to specific output hidden dimensions. Both phenomena have the same root cause (LLM scale creating systematic high-magnitude features) but different manifestations
- **Composite compressed format**: the SpQR representation (quantized weights + quantized scales + sparse outlier matrix) is the first to compose all three data types efficiently in a single GPU-compatible format
- **For HaLViT**: HaLViT at 11M–22M params is far below the 6.7B outlier threshold — systematic outlier patterns at the scale SpQR targets don't emerge. Standard uniform 3-4 bit PTQ should suffice for HaLViT without SpQR's outlier machinery. However, if the thesis involves a larger baseline model or scaling HaLViT up, SpQR defines the near-lossless frontier for 3-4 bit. Additionally, SpQR's sparse outlier mask for a shared W+Wᵀ weight pair is computed once and applies to both forward and transposed pathways — the sparsity structure is consistent across both uses without any special handling.

- **Extends** [[sources/2210.17323]] (GPTQ): builds on GPTQ's OBS-based Hessian sensitivity for outlier detection; adds bilevel quantization and sparse outlier storage on top; near-lossless vs GPTQ's moderate loss at 3-bit

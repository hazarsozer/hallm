## Problem

Hardware-aware NAS requires evaluating many candidate architectures, which is computationally expensive. Standard performance estimation options — training from scratch, supernet weight-sharing, accuracy predictors — are either slow, inaccurate, or require expensive dataset collection. The goal is a fast, hardware-aware search that avoids full training for evaluation.

## Method

**HW-EvRSNAS** reformulates HW-NAS as: *find the architecture whose layer representations are most similar to a reference model, subject to a hardware cost constraint*.

**Three components**:
1. **Representation Mutual Information (RMI) proxy**: Given a reference model (a high-performing pre-trained network), evaluate a candidate architecture by measuring the mutual information between its hidden layer representations and those of the reference model, using a single training batch. High RMI ≈ similar performance without full training.

2. **Genetic search**: Sample candidate architectures from the search space using an evolutionary algorithm. Fitness = RMI score + hardware penalty.

3. **Hardware penalty**: A continuous penalty term proportional to how far the candidate's hardware cost (latency on target device) is from the desired threshold. Guides search toward the hardware-feasible subspace without rejection sampling.

Evaluated on two different search spaces for image classification and on six different edge devices.

## Results

- Up to **8000× speedup** in search time compared to standard NAS literature
- Consistently finds hardware-feasible architectures across six edge device profiles
- Validated on two search spaces for classification tasks
- Lower CO₂ emissions due to drastically reduced compute for evaluation

## Significance

HW-EvRSNAS contributes a practical, compute-efficient HW-NAS pipeline by combining RMI proxy evaluation with continuous hardware penalties. The key insight — that representation similarity to a reference model is a strong proxy for task performance — avoids expensive retraining. This is the least central paper to the thesis's compression pillars (NAS is a lower-priority technique for the current scope) but is relevant if HaLViT's sharing configuration (which layers to share, at what rank) is automated via NAS.

For HaLViT: NAS formulations that include weight-sharing decisions as part of the architecture search space (e.g., which layers share weights, what the sharing topology is) are the most direct extension. HW-EvRSNAS's representation-similarity proxy could evaluate sharing configurations efficiently — replacing full training with a single-batch RMI evaluation of each sharing topology candidate.

## Problem

MoE-based LLMs (Qwen-MoE, DeepSeek-MoE) require vast, diverse training data to saturate their K expert subnetworks — each expert should be exposed to distinct domain signals. Federated learning (FL) could source this diversity from ubiquitous edge devices, but two fundamental obstacles block practical deployment:

1. **Model size**: Traditional FL assigns each edge device a full or pruned local MoE model. Even compact pruned MoE networks retain the gating architecture and are 3.3–9.3× larger than standard on-device LLMs — impractical for resource-constrained IoT hardware (iPhone 16: 8GB RAM, Jetson Nano: 4GB RAM).
2. **View-mismatch**: When edge devices use heterogeneous on-device LLMs (different architectures, different sizes), their latent spaces and prediction behaviors differ from the global MoE. Standard federated KD via logit alignment or feature matching assumes homogeneous architectures — both approaches fail across architectural boundaries.

## Method

**DeepFusion** is the first scalable federated MoE training framework enabling heterogeneous edge devices (each running their own on-device LLM) to contribute domain knowledge to a global MoE via KD, in a single communication round.

### Phase I — Local Knowledge Clustering

Each edge device n trains on-device LLM m_n on local private data; also sends low-rank feature embeddings e_n (semantically rich, tiny bytes, privacy-safe) to server.

Server constructs cosine similarity matrix Π ∈ ℝ^{N×N}:
```
π_{n1,n2} = (e_{n1} · e_{n2}) / (‖e_{n1}‖ · ‖e_{n2}‖)
```

KMeans clusters devices into K domain groups {C_i}^K_{i=1} matching the K MoE experts. Within each cluster C_i, a **local-knowledge proxy model** m̄_i is constructed by weight averaging:
```
m̄_i = (1/|C_i|) Σ_{n∈C_i} m_n
```

This yields K proxy models capturing K distinct domain knowledge bases, one per future MoE expert. Reduces N-device distillation to K-proxy distillation — constant overhead regardless of N.

### Phase II — Cross-Architecture Knowledge Distillation via VAA

Each proxy m̄_i (teacher) distills into a corresponding MoE base model M_i (student). The **view-mismatch problem**: m̄_i is a compact on-device LLM that builds global semantic features gradually (bottom-up, local-to-global); M_i is a standard LLM architecture that learns global semantics from the start. Direct logit alignment or shared-latent-space feature matching fails across this gap.

**View-Aligned Attention (VAA) module** (Fig. 5): enables student M_i to construct a feature representation whose predictive perspective aligns with teacher m̄_i's perspective. Three steps:

1. **Patch and project**: Student's intermediate features F^S from J representation stages are extracted, patched into P_q patches each, and projected to uniform dimension d via convolution layers C_j: F^S = Concat(C_1(F^S_1), ..., C_J(F^S_J)) ∈ ℝ^{P_q × d}

2. **Multi-head self-attention over cross-stage features**: F^{S'} = Softmax((W_q F^S)(W_k F^S)^T / √d) · W_v · F^S. This attention over the concatenated multi-stage features allows the student to learn to focus on different representation stages — blending its own processing hierarchy to match the teacher's compact architecture's perspective.

3. **Stage-divide and feature match**: F^{S'} divided back into J stage-sized chunks {F^{S'}_j}^J_{j=1}. Feature matching loss: L_FM = Σ^J_{j=1} MSE(F^T_j, F^{S'}_j). Combined KD loss:
```
L_KD = L_CE + α·L_FM + β·L_KL
```
where L_KL = KL(P^T_LLM, P^S_LLM) is logits-based distillation and L_CE is cross-entropy on hard labels.

VAA is architecture-agnostic — compatible with any teacher/student pair regardless of layer depth or hidden dimension.

### Phase III — Global MoE Model Assembly and Tuning

K base models {M_i}^K_{i=1} (each holding one domain's knowledge) are merged into global M_MoE:
- **FFN layers → Experts**: Expert i in M_MoE inherits M_i's FFN parameters directly. This is principled: M_i's FFN was specialized on domain C_i's training distribution.
- **Shared layers (embedding, self-attention, output) → averaged**: M^x_MoE = (1/K) Σ^K_{i=1} M^x_i. Aggregates cross-domain knowledge from all base models into the shared transformer backbone.

**Fine-tuning**: FFN-based experts are frozen (already domain-specialized). Gate layer M^gate_MoE is trained to compute optimal top-k expert selection probabilities p_i. Embedding, self-attention, and output layers are jointly fine-tuned on public benchmark data.

**One-shot FL design**: Each device uploads m_n exactly once. Communication cost F^net = Σ^N_{n=1} |m_n|. No iterative rounds — eliminates the dominant multi-round overhead of standard FL.

## Results

**Token Perplexity** (lower is better):

| Method | Qwen-MoE Medical MC-QA (N=128) | DeepSeek-MoE Financial Open-ended QA (N=128) |
|--------|-------------------------------|----------------------------------------------|
| FedJETS | 0.1571 | 4.0006 |
| FedKMT | 0.1546 | 4.0030 |
| OFA-KD | 0.1494 | 4.0333 |
| **DeepFusion** | **0.1494** | **3.9723** |

**Token Accuracy**:

| Method | Qwen-MoE (N=16) | DeepSeek-MoE (N=128) |
|--------|----------------|----------------------|
| FedJETS | 92.45% | 28.64% |
| FedKMT | 92.34% | 28.93% |
| OFA-KD | 92.38% | 28.95% |
| **DeepFusion** | **92.52%** | **29.22%** |

DeepFusion particularly excels on the challenging financial open-ended QA task (requires free-form reasoning), where feature-based VAA captures reasoning processes beyond logit alignment.

**Communication efficiency** (vs FedJETS):
- Up to **−71% communication cost** (one-shot vs. multi-round)
- FedJETS requires **3.3–9.3× more on-device memory** (local expert MoE model vs. lightweight on-device LLM)
- Performance within 1–5% of centralized DeepSpeed-MoE upper bound

**Ablation — heterogeneous vs. homogeneous teachers**: Heterogeneous on-device LLMs consistently outperform homogeneous setups, confirming that diverse predictive perspectives enrich the MoE's domain coverage.

## Significance

DeepFusion is the state-of-the-art in federated MoE training. Its two core contributions have broader significance:

1. **VAA module**: The view-mismatch problem is not unique to federated MoE — it appears anywhere two models with different architectures need to exchange knowledge. The VAA principle (multi-stage attention to blend cross-stage features and align predictive perspectives) is a general technique for cross-architecture KD.

2. **One-shot FL + KD composition**: Traditional FL sends gradients iteratively; DeepFusion sends a trained model once. The server does the KD computation (computationally intensive) rather than the edge devices (resource-constrained). This asymmetric computation split is a design principle for any future federated compression scheme.

**For HaLViT**: HaLViT's W and Wᵀ sharing creates an internal view-mismatch within a single forward pass — the W path and Wᵀ path process inputs from different architectural positions but through the same weight matrix. The VAA insight — using attention over multi-stage features to align distinct representation perspectives — could inspire an internal alignment mechanism that regularizes the two HaLViT paths to produce compatible intermediate representations, potentially improving the accuracy of the shared-weight assumption.

More directly: if deploying HaLViT at the edge in a federated setting, DeepFusion's framework could accommodate HaLViT as one of the on-device LLMs contributing to a global MoE. HaLViT's compact parameter count (11M–22M) makes it well-suited for the on-device teacher role.

## Contradicts / Supports

- Extends: 2301.05849 (Wu et al., 2024 federated KD survey) — DeepFusion is a concrete MoE implementation of federated KD from heterogeneous on-device models; validates the survey's privacy-preserving KD category
- Complements: 2409.08308v1 (DiReDi) — DiReDi uses reverse distillation for privacy-preserving edge adaptation (ΔKnowledge from edge to server); DeepFusion uses forward federated KD with VAA for view alignment; both address the privacy-preserving edge↔server knowledge transfer problem from opposite directions
- Outperforms: FedJETS (local expert model per device — memory-intensive), FedKMT (logit-level cross-size KD), OFA-KD (cross-architecture via logit+feature projection) on open-ended financial QA
- Approaches: DeepSpeed-MoE centralized upper bound — federated + one-shot communication nearly matches full centralized training

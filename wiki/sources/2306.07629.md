## Problem

LLM inference for token generation is **memory-bandwidth-bound, not compute-bound**. At batch size 1, the GPU spends most of its time loading model weights from DRAM, not performing arithmetic. This means that reducing weight storage directly reduces the primary inference bottleneck — a frame that changes how quantization should be designed. Existing methods (GPTQ, RTN) use uniform quantization bins, which cannot protect the small fraction of highly sensitive weights that account for most quantization error. At 3-bit uniform quantization, perplexity degrades significantly for 7B models, undermining the practical value of the compression.

## Method

SqueezeLLM introduces two complementary techniques that compose into the Dense-and-Sparse (D&S) framework.

### Technique 1: Sensitivity-Based Non-Uniform Quantization

Standard quantization uses uniform bins placed by weight range. SqueezeLLM places bins using **Fisher information** to weight each element's importance:

```
Fisher_ii = E[(∂L/∂w_i)²]
```

The Fisher information approximates the diagonal of the Hessian of the loss with respect to each weight. A higher F_ii means w_i has greater influence on the loss — rounding it costs more. Quantization bins are found via **gradient-weighted k-means** (GWK): minimize

```
Σ_i F_ii · (w_i - centroid(w_i))²
```

subject to k centroids. This places more centroids near the high-Fisher-information values, effectively giving sensitive weights finer quantization resolution. The centroids are stored as a lookup table (LUT); each weight index stores log₂(k) bits.

In CUDA, SqueezeLLM uses a **balanced hybrid kernel**: separate warp groups handle the dense LUT-quantized path and the sparse FP16 path in parallel, achieving load balancing for the hybrid representation.

### Technique 2: Dense-and-Sparse (D&S) Decomposition

Even with non-uniform bins, a small fraction of weights (outliers) incur irreducibly large quantization error because their values fall far from any centroid. SqueezeLLM identifies these weights and stores them separately in FP16:

```
W = W_dense + W_sparse
```

Where W_sparse stores the most sensitive and most extreme-valued weights at full precision. The selection criterion uses both Fisher sensitivity and magnitude to identify the worst offenders. Typical sparsity: **0.05% most sensitive + 0.4% outlier** weights stored in FP16, totaling ~0.45% of the weight count.

**Combined benefit**: non-uniform bins protect the bulk of weights; the sparse FP16 component protects the irreducible outliers that non-uniform bins cannot capture.

### Implementation

- Sparse weights stored in compressed format (COO/CSR compatible)
- LUT-based CUDA kernel with on-the-fly dequantization during matmul
- Balanced hybrid kernels split warps between dense (LUT) and sparse (FP16) paths for load balance
- No weight update needed — purely post-training calibration using Hessian estimates from a calibration set

## Results

### LLaMA — C4 Perplexity (3-bit, from Table 1)

| Model | FP16 | GPTQ 3-bit | SqueezeLLM 3-bit | Improvement vs GPTQ |
|-------|------|-----------|-----------------|---------------------|
| LLaMA-7B | 7.05 | 9.55 | **7.75** | **2.1× better PPL gap** |
| LLaMA-13B | 6.61 | 8.52 | **7.67** | ~1.7× better PPL gap |
| LLaMA-30B | 5.98 | 6.66 | **6.56** | |
| LLaMA-65B | 5.62 | 6.12 | **6.02** | |

At 3-bit, SqueezeLLM achieves **2.1× better perplexity gap** to FP16 compared to GPTQ at the same memory budget. The improvement is sharpest at 7B–13B, the scale most relevant for edge deployment.

### Memory and Speed

| Metric | Value |
|--------|-------|
| Memory compression | ~3× vs FP16 (3-bit dense + 16-bit sparse) |
| Inference speedup | **2.3–2.4× vs FP16** on A6000 GPU |
| vs GPTQ at same memory | Equal memory, superior perplexity |

The speedup is the direct consequence of the memory-bandwidth-bound framing: fewer bits loaded → fewer memory transactions → faster generation. The sparse component adds minimal overhead (~0.45% of weights) and is handled by the balanced CUDA kernel.

### Component Ablation

| Method | LLaMA-7B 3-bit PPL (C4) |
|--------|-------------------------|
| RTN (uniform, no outlier) | ~28 |
| GPTQ (uniform, OBS-based update) | 9.55 |
| SqueezeLLM — non-uniform bins only | ~8.5 |
| SqueezeLLM — D&S only (uniform + sparse) | ~8.2 |
| **SqueezeLLM — full (non-uniform + D&S)** | **7.75** |

Both techniques contribute; they are complementary. Non-uniform bins give the larger share of improvement; D&S handles the residual outliers that bins cannot accommodate.

## Significance

- **Memory-bandwidth framing is the correct lens for quantization design**: the bottleneck in LLM inference is not compute efficiency but weight-loading throughput. Reducing bits-per-weight directly reduces the primary bottleneck. This reframes why 3-4 bit quantization matters even when INT8 compute is available.
- **Fisher information is the right sensitivity proxy for quantization**: OBD/GPTQ use the Hessian for weight compensation; SqueezeLLM shows the diagonal Fisher (which approximates the Hessian diagonal without costly inversion) is sufficient for identifying quantization-critical weights.
- **Independent concurrent validation of D&S paradigm**: SpQR [arxiv:2306.03078] independently arrived at the same Dense-and-Sparse decomposition at the same time. Two separate research groups (UW/ETH Zurich vs UC Berkeley) found the same structural solution, confirming it as the correct approach to near-lossless 3-4 bit compression. The difference: SpQR uses OBS-based sensitivity and bilevel group quantization; SqueezeLLM uses Fisher-based non-uniform bins.
- **For HaLViT**: HaLViT at 11M–22M params is below the scale where systematic outlier phenomena emerge. Standard uniform PTQ suffices at this size. However, the Fisher-weighted k-means approach applies to any model — for a shared W+Wᵀ weight in HaLViT, the Fisher information accumulated during calibration spans both the W→x and Wᵀ→x' pathways (gradient accumulates from both uses of shared W in one backward pass), making the non-uniform bin placement naturally joint across both contexts without modification.
